# 企业试点接入与验收

## 现在实际可用的范围

可嵌入 Node.js 24+ 的后端，服务一个明确配置的租户/项目/环境/流程。企业适配器只提供已验身份接口，不提供账号库、默认账号、直接监听或对外模型调用。审批者确认的是**流程定义的草稿变更**，不是对某个采购申请审批。不要把演示服务部署为企业服务。

| 角色 | 看共享草稿 | 准备本人提案 | 确认本人提案 | 看操作审计 |
| --- | --- | --- | --- | --- |
| viewer | 是 | 否 | 否 | 否 |
| editor | 是 | 是 | 否 | 否 |
| approver | 是 | 是 | 是 | 否 |
| auditor | 否 | 否 | 否 | 是 |

本版不允许把一个人的提案交给另一个人确认；不宣称双人会签。编辑者可准备并查看本人提案供人工讨论，实际提交须由审批者自行准备并确认。授权配置经宿主创建时做快照，角色调整需要宿主重建相应适配器。会话撤销由身份适配器在每次校验时反映；写入前复查。

## 连接宿主

1. 由企业宿主建立同源 HTTPS 入口；只用企业已验证会话作为 `identify(request)`，返回稳定的签发者与主体组合标识（最多 120 字符）。身份验证失败返回 `null`，不能信任浏览器传来的身份头、参数或请求体，也不能相信未校验的转发头。
2. 在受限数据目录用 `new ProposalStore(absoluteDatabasePath)` 建单节点文件数据库。执行有授权的离线初始化 `store.putInitialDraft({userId: realAdmin, workspaceId, projectId, environment}, workflowId, validatedWorkflow)`，它不会覆盖已有草稿。过往个人版草稿不会隐式迁移为企业共享草稿。
3. 用 `createPilotHttp({origin,target,identify,memberships,store})` 获取 Fetch handler，把源站 `/v1/ai/workflows/<workflowId>` 子树转发给它。`origin` 使用标准 HTTPS origin（无末尾斜杠）；`target` 明确声明 `workspaceId`、`projectId`、`environment`、`workflowId`，每条 membership 包含相同范围及 `actorId` 和 `role`。写请求带精确同源 `Origin`，禁止在企用宿主挂载演示脚本。
4. 宿主负责 TLS、企业 SSO、用户角色运维、限流、并发控制、健康监测、审计保留、库文件权限和加密备份。不要把数据库文件交给多实例共享写入。应用接口只读审计不等于防 DBA 篡改。备份需使用一致性 SQLite 备份并在独立进程演练恢复。

## 接口

以下为配置流程 URL 的后缀：
- `GET /v1/ai/workflows/<workflowId>`（无尾部斜杠）：共享草稿与版本。
- `POST /proposals`：`{ "expectedRevision": 1, "operation": { "kind": "set_amount_threshold", "edgeId": "e3", "value": 80000 } }`。返回 201 的提案，不写草稿。
- `GET /proposals/<id>`：提案创建人可取回自己的提案，须有可读权限。
- `POST /proposals/<id>/confirm`：`{ "expectedRevision": 1 }`。仅有权限的创建人可确认。版本不符返回 409；同一成功确认可获得原回执，不重复写版本或审计。单个事务保存已确认草稿、上个版本备份和审计所需元数据。
- `GET /audit?limit=25&before=42`：审计员按新版本号降序查看确认事件。省略 `before` 从最新开始；有 `nextBefore` 则可续查，可能返回空页。记录操作者、目标、修改值、时间及新旧版本，不含提示语、附件或完整草稿。未获授权、失败尝试及读取行为尚不写入这里，企业宿主需补访问日志。
- 试点默认不能运行模型或上传；没有生产审批发布路由。

## 本地验证

运行 `npm ci` 后，`npm run check:pilot` 使用合成流程和模拟身份验证隔离与重启恢复，不需要模型密钥，不运行企业身份服务。

## 正式试点验收闸门

1. 接入客户 SSO 和真实角色，在客户沙箱验证账号撤销、访问隔离、同源 HTTPS，以及多人同时确认冲突。
2. 用隔离环境执行备份、异机恢复和数据库完整性检查，再确定数据保留与告警目标。
3. 将企业操作界面接入后端，验收至少一个真实业务角色可独立完成：编辑、预演、核对、确认。涉及双人会签的组织要先实现角色分离和指定复核，不得用本人确认替代。
4. 连接独立 Odoo 测试库，先做只读字段/角色映射和无写入 Dry Run，再验证发布、停用与回滚。不能用浏览器预演代替 Odoo 执行验收。
5. AI 单独验收；先用合成材料测真实多模态输出，再评估数据外发政策、凭据、并发预算和人工确认。支持附件不等于获准外发业务材料。

### 挂接业务页面（v0.6）
将生产构建的静态资源与该 API 置于同一已验证 HTTPS 源站，从已登录入口打开 `?workflow=<workflowId>`。页面只接受受控格式的流程标识，不从 URL 读取身份、权限或 API 域名。角色能力由 GET 返回，仅用于引导页面；服务端另行检查每个动作。审计 API 仍独立，无审计角色前端或企业登录页。
